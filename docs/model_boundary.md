# Model boundary and data contract

Дата: 2026-09-29.

Документ подготовлен по команде 2 из
`TZ_Scoring_RAG_Agent_Production_v2.md` и опирается на
`docs/baseline.md`.

## Граница модели

Текущая модель LightGBM прогнозирует риск для одной строки наблюдения кошелька,
а не для произвольного `wallet_address` целиком. У одного кошелька может быть
несколько строк, поэтому агрегирование до уровня кошелька является отдельным
правилом поверх строковых оценок.

Идентификатор сущности: `wallet_address`.

Целевая переменная: `target`.

Кандидат на момент прогноза: `borrow_timestamp`. Это рабочая гипотеза для
проверок, а не окончательно подтвержденный бизнес-контракт. В исходных данных
нет отдельного manifest/provenance, который доказывает время формирования
каждого признака.

Текущее API `/predict` принимает признаки строки. Запрос только с адресом не
имеет проверенного feature store и не должен тайно получать строку из test.

## Смысл строки

Одна строка описывает состояние/историю кошелька вокруг события займа или
наблюдения, включая:

- адрес кошелька;
- временные поля транзакционной истории;
- агрегаты входящих/исходящих транзакций;
- рискованные транзакции и контракты;
- lending/borrowing/deposit/withdraw агрегаты;
- рыночные технические признаки;
- метку `target`.

Точная семантика горизонта агрегации и источник метки пока не доказаны
документально. Поэтому сохраненные метрики считаются метриками конкретного
строкового offline-запуска, а не production-качеством решения.

## Доступность признаков

Текущий статус доступности признаков:

- `borrow_timestamp` и `borrow_block_number` удаляются до обучения, но
  `borrow_timestamp` используется как кандидат на момент прогноза при аудите.
- `first_tx_timestamp`, `risky_last_tx_timestamp`,
  `risky_first_last_tx_timestamp_diff`, `time_since_first_deposit`,
  `time_since_last_liquidated` и `wallet_age` остаются модельными временными
  признаками и требуют подтверждения, что они были доступны на момент
  `borrow_timestamp`.
- Агрегаты вида `*_sum`, `*_avg`, `*_count`, `*_ever`, `total_*` требуют
  отдельного описания окна расчета. Без окна нельзя доказать, что в них не
  попали события после момента прогноза.
- Рыночные признаки `market_*` требуют описания даты/окна рынка, относительно
  которого они были рассчитаны.

## Проверка временной утечки

В рамках команды 2 выполнена безопасная проверка timestamp-полей относительно
`borrow_timestamp`.

Результат:

- `first_tx_timestamp > borrow_timestamp`: `0` строк.
- `risky_first_tx_timestamp > borrow_timestamp`: `0` строк.
- `risky_last_tx_timestamp > borrow_timestamp`: `0` строк.
- `last_tx_timestamp > borrow_timestamp`: `202` строки.

`last_tx_timestamp` входит в текущий список 65 модельных признаков. Это не
доказывает утечку автоматически: возможно, строка не является прогнозом на
момент займа или `borrow_timestamp` не является правильным proxy. Но текущий
статус временной границы - `requires_review`, пока не будет подтверждено, что
все признаки доступны на выбранный момент прогноза.

## Split

Split выполняется по `wallet_address` с seed `42` и стратификацией по
кошельковому `max(target)`.

Фактические размеры:

- train: `226306` строк, `37238` кошельков;
- validation: `110570` строк, `18619` кошельков;
- test: `106085` строк, `18619` кошельков.

Пересечения кошельков:

- train/validation: `0`;
- train/test: `0`;
- validation/test: `0`.

Split по кошелькам защищает от попадания одного адреса в разные выборки, но сам
по себе не закрывает временную утечку внутри строки.

## Data manifest

Добавлен воспроизводимый manifest:

- `data/data_manifest.json`

Manifest фиксирует:

- SHA256 `data/dataset.parquet`;
- схему столбцов;
- количество строк, столбцов, уникальных кошельков и распределение `target`;
- seed и стратегию split;
- хеши групп кошельков train/validation/test;
- список модельных признаков;
- результат временной проверки;
- версии зависимостей из `requirements.txt` и установленные версии;
- сохраненные test-метрики и top-50 summary.

## Метрики и ограничения

Существующие test-артефакты сохранены без изменения:

- `results/LightGBM_metrics.json`;
- `results/LightGBM_classification_report.txt`;
- `results/LightGBM_top50_risky_wallets.csv`;
- `results/LightGBM_top50_risky_wallets_evaluation.csv`.

Фиксированные показатели:

- threshold source: validation F1;
- threshold: `0.3578026090255801`;
- test ROC-AUC: `0.8722954225342738`;
- test accuracy: `0.8006692746382618`;
- class 1 precision/recall/F1:
  `0.7226852205826133 / 0.7342119572253437 / 0.728402990058825`.

Ограничения:

- показатели строковые, не кошельковые;
- они не являются оценкой RAG/Agent;
- `predict_proba` не подтвержден как калиброванная вероятность реального
  мошенничества;
- новые production labels не подключены;
- синтетические labels не использовать как evidence качества;
- temporal leakage review открыт.
